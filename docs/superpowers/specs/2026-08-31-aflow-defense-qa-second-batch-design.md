# AFlow 开题答辩第二批问答稿设计说明

## 目标

针对用户提供的九个评委问题，生成与第一批问答稿一致的中文答辩材料。正文优先提供直观、可直接口述的回答，随后给出代码和实验依据，并严格区分当前实现与后续研究。

## 输出文件

`/Users/majiatong/lab/汇报/20260831开题答辩重点问题与回答_第二批.md`

## 组织方式

按照原问题顺序，分为 M、S/O/V、R 和跨领域泛化四部分。每题包含：

1. 一句话核心结论；
2. 30—60 秒推荐口述回答；
3. 技术依据与当前实现；
4. 可能追问及应对；
5. 当前边界与后续计划。

文末增加关键数字速查表和高风险表述修正。

## 事实边界

- 当前稳定失败判据只能在固定模型与实验协议下提供可复现证据，不能证明模型存在与 Prompt 和采样无关的绝对能力缺口。
- 当前尚未正式完成 Prompt 扰动、温度分层和跨模型验证。
- 人工参与错误审计、机制边界确认、题族和元结构设计；系统自动执行运行、聚合、规格填写、候选生成、验证和固定门槛判断。准确称谓是半自动闭环。
- 参数化隐藏集验证同机制跨实例复用，不等同于验证未见机制；公开基准的预训练污染也无法仅靠数据划分彻底证明不存在。
- 多目标公式中的连续权重尚未确定；当前原型使用预注册硬门槛。成本已记录但尚未设正式硬阈值。
- 当前路由对活动算子做确定性规则扫描和证据排序，不调用 LLM。双算子结果不能直接证明 50—100 个算子时仍可靠。
- 新的负证据可能使算子无法通过路由证据门槛，库也支持设置 `retired`；基于滚动窗口的自动降级、再验证和淘汰策略尚未完整实现。
- 成本公平性需同时进行在线等预算比较、端到端总成本比较和准确率—成本 Pareto 分析。

## 验收标准

- 九个问题逐题直接回答。
- 口述答案可在约 30—60 秒内完成。
- 明确回应质疑成立的部分，不回避人工成本、验证器依赖和扩展性限制。
- 当前数字与代码、冻结协议一致。
- 不把规划中的方法描述为已完成结果。
- Markdown 可直接用于答辩准备，无 Obsidian 专属标记。
