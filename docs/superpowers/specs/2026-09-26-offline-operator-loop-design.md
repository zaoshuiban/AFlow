# 自动化离线算子闭环

用户已确认的方向：先完善现有离线系统，不做在线更新。本次实现一个完整、可审计的离线入口，不运行付费实验，不覆盖现有两个算子及正式实验材料。

## 边界与路线

采用独立运行目录的编排器，复用现有规格生成、固定骨架编译、质量指标及证据感知路由。与直接串接旧脚本相比，它明确分开开发集选拔和隐藏确认；与在线系统相比，它不在正式评测过程中学习。

一个运行处理一个机制假设、生成一批候选、最多晋级一个候选。暂不承诺自动发现新算法：当前后端为 prompt-only 的 single_step / two_stage / verify_fix，禁止自动执行自由生成的 Python。真正可复用算法程序的通用合成是下一阶段。

## 数据与状态流

1. prepare：用户提供有训练来源声明的 JSONL；去重、排除本地 validate/test 及额外指定排除集，固定种子划分 discovery / design / gate / regression；冻结文件和运行代码哈希。
2. discovery：对 discovery 所有题重复运行通用两阶段基线。执行异常和超时单独记录，不算作数学机制失败。按已有可解释特征分组；达到不同题数、重复失败次数和错误率门槛后，选择一个机制假设。有限样本和粗粒度特征不构成因果证明。
3. generation：只把选中发现组的题目、答案、失败输出送入诊断和规格生成。规格、编译后的程序和拒绝条件保存到本次运行的算子库，候选不能进入正式路由。
4. design：开发集用于候选比较。由发现阶段固定的特征谓词确定专项子集，不能为每个候选换分母。按既有质量函数选出一个通过开发门槛的候选。
5. freeze：冻结候选代码、版本、路由契约和指标阈值；冻结隐藏专项题与回归题索引。隐藏池只按已冻结的题面特征筛选，不能按答题结果筛选。
6. gate：只验证该一个候选。专项检查能力，回归集通过实际候选尝试和基线回退测量端到端结果、时延及 Token。配对执行顺序由种子确定，结果逐项保存。隐藏失败后归档，不再选择第二名重考。
7. promotion：写入版本绑定、作用域匹配的隐藏证据，在本次运行副本安装候选，检查现有路由器确实能选择该候选。不满足则拒绝。原算子库、模板和实验目录只读。
8. summary：输出状态、失败原因、分母、覆盖率、已报告 Token、未知用量和人工参与边界；不把开发/晋级结果称作独立最终测试成绩。

## 中断、预算与完整性

- 单写者文件锁；各阶段和单个执行结果原子保存。
- 模型请求在发送前记账，关闭 SDK 自动重试；请求级缓存包含输入哈希，恢复时不能更换提示词后复用答案。
- 请求已发出但未保存结果时，恢复后按失败/用量未知处理，不盲目重发；格式修复属于独立计费请求。
- 固定请求次数和单次最大输出 Token，不提供未经核实的美元报价。未知用量不得记成免费。
- 数据、配置（不含密钥）、运行代码或冻结候选发生变化时拒绝继续；密钥不写入 manifest。
- 只在用户明确执行 run --allow-api 时调用模型；prepare、status、测试均不调用 API。
- 不自动下载训练数据，不将 math_validate、math_test 或 MATH-500 当作发现数据。

## 验收清单

- [x] 新增协议/持久化、模型适配与离线编排入口。
- [x] 无网络测试走通晋级分支、无稳定失败分支、开发失败、隐藏失败、路由拒绝。
- [x] 验证数据交叉污染、哈希漂移、重复执行、请求预算与单写锁。
- [x] 验证生成器从未收到隐藏集/回归集的题目和结果。
- [x] 验证原库和原模板不变，报告不虚构费用或“新能力”结论。
- [x] 输出中文使用说明，并运行相关回归测试。

补充：当前可用技能中没有 writing-plans；以上作为本次实现计划。数据隔离是编排层的访问约束，不是操作系统沙箱，也不能证明训练模型从未见过某道公开题。
