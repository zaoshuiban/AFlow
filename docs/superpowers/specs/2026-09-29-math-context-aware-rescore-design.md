# MATH 题面感知评分与冻结运行旁路复评设计

## 目标

修复真实发现试跑暴露的两类确定性评分误差：选择题只输出选项字母时未映射到选项内容；普通文本标签因大小写不同被判错。使用保存的模型回答离线复评，同时完整保留 `pilot_20260926_001` 的冻结输入、请求、检查点与原始结论。

本次只改评分与复评，不扩大训练发现池、不重新调用模型、不回写原实验结果，也不把仍有歧义的图形题自动判为正确。

## 采用方案及替代方案

采用“题面感知、受控归一化、旁路复评”：评分入口额外接收原题文本；只有解析出完整选择题结构时才解释单个选项字母；只有纯文本标签才允许大小写无关比较；复评产物写到独立审计目录。

未采用两种更宽松方案：其一是全局 `casefold`，它会错误合并数学变量 `A/a`、`X/x`；其二是从推理正文中搜索数值答案，它会引入多个中间数值之间的选择歧义，并改变“最终答案”协议。

## 评分规则

### 选择题映射

1. 从题面识别按顺序出现的明确选项标记，例如 `(A)`、`\text{(A)}`、`\textbf{(A)}`，并切分到下一个选项标记。
2. 至少解析出两个不同标签，标签不得重复；对应内容必须非空。若结构异常或切分不完整，放弃映射，沿用普通判分。
3. 仅当最终预测在去除 `\text{}` 等展示包装后是单个 `A`–`Z` 字母，并且题面存在该标签时，才将预测替换为对应选项内容后与参考答案比较。
4. 参考最终答案若本身是单个选项字母，可按同一题面映射；原始提取答案继续写入审计记录。
5. 不从推理正文推断“模型其实想选哪一项”，不根据参考答案反向猜选项。

### 文本大小写

1. 先执行现有展示规范化，再判断是否属于纯文本标签。
2. 只有由至少两个 Unicode 字母构成，并允许内部空格、连字符或撇号的标签，才使用 `casefold()` 比较；例如 `Orange=orange`、`MAKE=make`。
3. 单字母内容始终大小写敏感；含数字、运算符、反斜杠命令、上下标、括号或其他数学结构的表达式也保持大小写敏感。因此 `A≠a`、`x≠X`。
4. 文本标签内容仍需完全相同，`MAKE≠MADE`。

评分器版本由 `math_equivalence_v8` 提升为新版本，并在测试和复评报告中记录源码哈希。

## 旁路复评

新增面向离线闭环发现阶段的复评入口。输入是：

- 冻结运行的 `manifest.json` 与 `inputs/discovery.json`；
- `checkpoints/discovery/baseline/<problem_id>/*.json` 中已保存输出；
- 原始 `checkpoints/screen.json` 与 `summary.json`；
- 当前评分器及其版本。

复评器只读上述文件，先记录每个来源文件的 SHA-256，再用“题面、参考解答、已保存预测”重新计算分数。执行异常继续排除，绝不因为新评分规则改成数学失败或成功。随后在相同冻结阈值下重新计算机制分组，但输出仅作为反事实审计，不恢复或继续已经归档的运行。

输出写到新的、禁止覆盖的 `results/math_train_readiness_20260926/pilot_rescore_v9/`：

- `details.jsonl`：每次观察的原分数、新分数、提取答案、选择题映射、翻转原因和原错误字段；
- `summary.json`：新旧正确/错误/异常计数、新旧机制筛选结果、翻转题目、仍失败题目、输入哈希、评分器版本与限制；
- `human_audit.md`：便于人工核对的题目级摘要，不把自动结果表述为能力缺口证明。

原运行目录保持字节级不变。即使新评分结果改变结论，也只报告“按新评分规则离线复评会得到什么”，不能修改原 `archived_no_stable_mechanism` 状态，也不能沿用其隐藏池继续生成候选。

## 测试与验收

新增以下正反例：

- 题面 `(A) 2 ...`，预测 `A`，参考 `2`：正确；预测 `B`：错误。
- 题面 `\textbf{(C)} 16`：能够映射；缺失、重复、空选项或非选择题中的 `A`：不映射。
- `Orange` 与 `orange`：正确；`A/a`、`x/X`、`MAKE/MADE`：错误。
- 原有分数、矩阵、坐标、LaTeX、集合及不完整表达式测试保持通过。
- 复评测试证明源运行文件哈希前后不变、输出不可覆盖、异常观察不参与机制错误率、结果可由保存答案确定性重现。
- 完整测试套件通过；复评真实 `pilot_20260926_001` 时不创建任何 API 请求，并输出独立审计文件。

## 决策门槛

复评完成后再决定是否扩大池：

- 若去除格式误判后仍有至少一个满足原门槛的稳定机制组，另建全新冻结运行验证；不能续用已归档运行。
- 若只有零散真实失败，先扩大独立发现池或改善机制表征，但不得降低原门槛来强行生成算子。
- 若剩余失败主要是含图输入、执行异常或评分歧义，先分别完善输入能力、调用稳定性或评分审计，不能混称为算子能力缺口。
