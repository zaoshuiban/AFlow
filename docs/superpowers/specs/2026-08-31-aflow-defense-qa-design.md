# AFlow 开题答辩重点问答稿设计说明

## 目标

生成一份面向开题答辩的中文 Markdown 问答稿，使听者能先通过直观语言理解结论，同时允许答辩人在追问时给出与当前代码和冻结实验记录一致的技术依据。

## 输出位置

正式文件拟保存为：

`/Users/majiatong/lab/汇报/20260831开题答辩重点问题与回答_直观版.md`

## 组织形式

采用逐题答辩卡片式结构。每个主要问题依次包含：

1. 一句话核心结论；
2. 30—60 秒推荐口述回答；
3. 技术依据与当前实现；
4. 可能追问及应对；
5. 当前局限与不能夸大的边界。

文末增加一页“答辩速查表”，集中列出关键数字、阈值和高风险措辞。

## 内容范围

问答稿覆盖以下主题：

1. 稳定失败机制的统计判据与阈值来源；
2. 自动生成算子与单题临时代码生成的本质区别；
3. 结构化规格的作用、自动化程度及受约束模板；
4. 数据隔离、隐藏集泄漏与算子版本更新规则；
5. 多算子适用范围重叠时的冲突处理和证据感知特征；
6. 执行前拒绝、执行后回退及 180 秒总超时；
7. 在 486 道自然 MATH 测试题上的整体净收益验证计划；
8. 迁移到代码生成等非数学领域时的反馈与归因问题；
9. 双算子联合实验中三次非专项新增错误的逐次还原。

## 必须保持准确的事实边界

- 当前稳定失败筛选使用三层规则：排除评分与执行异常；同题独立运行 3 次、至少失败 2 次；同机制审计错误率不低于 0.20，且至少包含 3 道不同的稳定失败问题。
- `tau_e = 0.20` 是当前预注册的操作阈值，不是理论常数。后续计划比较 0.15、0.20、0.30。目前没有把 Wilson 或 Clopper–Pearson 置信下界实现成硬门槛。
- Design Set 用于规格形成和候选开发，因此对生成器可见；Hidden Gate Set 在版本冻结前不可见；Regression Set 用于检查非专项副作用。
- 若隐藏题内容、答案或失败轨迹被用于修改候选，该隐藏集从此转为开发证据。新版本必须在新的冻结隐藏集上重新验证。
- 当前路由器以适用特征、禁止特征、硬失败边界、版本绑定的历史胜负证据和最低分数 0.70 进行选择。面向几十或上百个算子的冲突裕量、分层检索和不确定性校准属于后续研究。
- 180 秒是一次完整求解的总墙钟时间上限，包含路由、算子执行和可能发生的回退，不是每个阶段分别获得 180 秒。
- 当前仓库自然 MATH 测试集为 486 题，不写成“完整 MATH 500”。
- 三次非专项新增错误是三个重复运行观测，只涉及两道题：时钟概率题在第 1、2 次运行中由通用回退分别回答为 `5/36` 和 `37/180`；单位根求和题在第 3 次运行中触发 180 秒总超时。三次均未选择专项算子，不属于误路由。

## 表述原则

- 优先使用“安检、毕业考试、工具说明书、拒绝服务”等直观类比，但随后给出精确定义。
- 已实现内容使用“当前代码中”；设计或规划内容使用“后续计划”，不把规划说成现状。
- 不把开发集高分等同于可信，不把参数化隐藏集结果等同于自然分布泛化结论。
- 不声称当前系统已经完全自动完成从任意失败日志到复杂新算法的全过程。
- 不把三次非专项损失解释为专项算子副作用；同时承认这说明通用回退仍有随机性和超时风险。

## 验收标准

- 用户列出的所有主问题和追问均有直接回答。
- 每题口述部分能在约 30—60 秒内说完，语言适合现场表达。
- 所有关键数字可追溯到当前代码或冻结实验文件。
- 清楚区分“当前实现”“当前实验结论”和“后续研究计划”。
- 三次非专项新增错误逐条列出题目类型、运行序号、基线结果、路由结果、是否选择算子及失败原因。
- Markdown 无 Obsidian 高亮标记等不适合正式打印的语法。
