# 历史资源受限失败到可执行算子闭环

用户明确批准直接实现已有历史回放路线，不新建题库、不重新校准、不要求数学错答。沿用已确认的 brainstorm 设计边界，不重复请求相同方案许可。

- 新 operational replay 模式读取旧冻结证据，仅验证归档完整性，不要求旧 runtime 哈希等于新 runtime。
- 生成前用资源失败计数授权；引用的是客观未完成记录，不授予原语义诊断 true 标记。
- 生成两个可复用 solve(problem) 函数并冻结，旧代码不暴露；用 AST 白名单及独立 CPU/墙钟受限进程执行，记录完整工具轨迹。
- 复用现有 OfflineLoop 的开发比较、唯一候选冻结、确认、隔离发布；通过 baseline_is_infrastructure 扩展点区分资源失败和网络故障，原语义模式保持原行为。
- 原始请求、候选代码、证据引用全链路哈希绑定；任何网络无效配对、确认失败或生成失败应归档，不绕过规则。
- 免费模拟链路及真实本地 worker 验证后冻结历史素数实验；实际付费 run 单独执行。

写作与实现计划已包含于此；writing-plans 技能当前不可用，不作为执行依赖。
